# Pista 2. Las piezas

- `region` sale de un `<section>` con nombre. El nombre lo toma de un título si lo conectas con `aria-labelledby` apuntando al `id` del `<h2>`.
- `spinbutton` es el rol de un `<input type="number">`. `combobox` es el de un `<select>` con sus `<option>`.
- El nombre de cada campo viene de un `<label>` cuyo `htmlFor` coincide con el `id` del campo.
- El botón lleva la clase `.reserva-boton`, va dentro de un `<form onSubmit={...} noValidate>` con `type="submit"`, y la validación ocurre en el `onSubmit` del formulario (no olvides `evento.preventDefault()`). El atributo `noValidate` evita que la validación nativa de `min`/`max` en `<input type="number">` bloquee el envío antes de que corra tu `onSubmit` con `aria-invalid` y `role="alert"`.
- Para el error, guarda el mensaje en estado. El campo lleva `aria-invalid` y `aria-describedby` con el `id` del párrafo del mensaje, y ese párrafo lleva `role="alert"`.
- En el CSS, `display: grid` va con `grid-template-columns`, `display: flex` alinea la fila de acciones y `.reserva-boton:focus-visible` dibuja un `outline` visible cuando el foco llega por teclado.

Si quieres ver la estructura completa, abre [la pista 3](3.md).
